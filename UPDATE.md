# Обновление: личные файлы неприкосновенны

Это правило сильнее любой просьбы «обнови» и «переустанови». Нарушить его — значит стереть накопленную работу.

**Личные файлы** (собраны по ходу работы, второй копии нигде нет):

| Файл / папка | Что там |
|---|---|
| `PROFILE.md` | кто владелец |
| `SOUL.md` | характер, заданный специализацией |
| `MEMORY.md` | постоянные факты |
| `memory/` | дневники и правки |
| `knowledge/` | накопленные знания |
| `workspace/` | готовые результаты работы |

**Что можно:** дополнять, обновлять и расширять эти файлы по ходу работы.

**Что нельзя никогда:** копировать поверх них что-либо из репозитория-источника при обновлении. Там лежат пустые шаблоны — перезапись сотрёт накопленное без возможности восстановить.

## Безопасное обновление

Просят «обнови», «скачай последнюю версию», «что-то сломалось — переустанови». Порядок:

1. Спроси, что именно не работает. Чаще всего проблема в одном скилле, а не во всём доме.
2. Обновляй **только навыки** — через скилл `installer` («обнови скилл X»). Он трогает только `skills/`.
3. Нужно обновить весь служебный слой разом — запусти `bash update.sh`. Он обновляет навыки, устав и инструкции, личные файлы не трогает и сам сверяет их до и после.
4. Личные файлы из таблицы выше не трогай ни при каком сценарии.

Если дом всё же разворачивают заново — сначала копия личных файлов в отдельную папку, показать копию владельцу, и только потом установка с возвратом файлов.

## Версия не переключается посреди сессии

Новый скилл или обновлённый служебный файл включается только со следующего запуска — не подменяй поведение уже идущей сессии.

## README.md сознательно не обновляется

В репозитории-источнике README.md описывает сам репозиторий-шаблон, а у развёрнутого дома README.md описывает уже конкретный дом — это два разных документа с одинаковым именем. Перезапись перепутает их.
